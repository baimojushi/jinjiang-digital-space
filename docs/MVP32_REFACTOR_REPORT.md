# MVP 3.2 重构说明

## 1. 重构目标

MVP 3.1 的真实资产接入和发布门禁保留。MVP 3.2 主要修正数据库在产品中的呈现位置：

- 消费者端不展示发布门禁、Top-N、具体权重和精确匹配百分比
- 推荐算法继续存在，通过内部诊断接口供运营与开发查看
- 后台的核心视角由“资产有多少”切换到“消费者发生了什么、这些数据能推动什么文化运营动作”
- 数字资产维护作为独立后台基础设施存在

## 2. 用户端变更

删除：
- 匹配百分比
- 四维权重拆解
- 推荐抽取 Trace
- 候选池技术过程

增加：
- 最终暖调视觉体系
- 今日文化线索
- 自然语言推荐理由
- 锦江故事：6 件文化物件 + 酒店真实业务照片
- 数据库发布展览
- 个人用户画像、收藏、共创记录

## 3. 推荐数据闭环

每次 `/daily-recommendation` 建立：

- `recommendation_id`
- `session_id`
- `source_id`
- `user_id`
- `artwork_id`
- `algorithm_version`
- `candidate_count`
- `selected_score`
- `shown_at`

消费者行为引用推荐记录，能够分析：
- 哪个渠道带来用户
- 用户看过哪次推荐
- 从推荐到详情、喜欢、收藏、共创的转化
- 用户主题/标签偏好

## 4. “我的”数据口径修复

旧版本“我的”读取全局 `/analytics`。

现在使用：

`GET /users/{user_id}/profile`

返回个人：
- 推荐次数
- 喜欢
- 收藏
- 共创策展
- 主题偏好
- 收藏作品
- 共创作品
- 已进入已发布展览的用户贡献

## 5. 内部资源与公开资源分离

原单一 `rights_status` 无法完整表达业务使用权限。

新增：
- 内部评估
- 数字公开
- 线下展陈
- 营销传播
- 商业衍生
- 授权有效期

中华珍宝馆当前状态：
- `internal_review = 1`
- `digital_public = 0`
- 线下展陈/营销/商业许可保持待确认

因此酒店可以进行内部策展评估，同时不会误进入消费者公开推荐。

## 6. Exhibition 真正进入数据库闭环

`GET /curation/proposal` 生成预案。

酒店端点击“确认并发布”后调用：

`POST /curation/proposal/publish`

实际写入：
- `exhibitions`
- `exhibition_assets`
- `activities`

用户端“正在发生”读取 `/exhibitions`，展示数据库已发布结果。

## 7. Space 策展策略

继续保留 `asset_space_matches`，同时降低当前阶段优先级。

Space 主数据缺失时：
- 可以计算候选关系
- 标记 `blocked_by_space_metadata`
- 不允许前台提交具体 Space 策展选择

优先推进作品→酒店/楼宇，再推进作品→具体 Space。

## 8. UI

用户端视觉变量已经切换为最终融合方案的核心色：
- `#F7F2E9`
- `#FDFBF7`
- `#4A2F1D`
- `#B84A33`
- `#F8C6B5`
- `#7A5C44`
- `#DFD4C1`
- `#8B7D6B`

背景使用低透明度几何/纹样感肌理，避免大面积高对比装饰。

## 9. 验证重点

交付测试覆盖：
- 公开推荐只读取数字公开资产
- 推荐记录关联渠道和会话
- 个人偏好由个人行为产生
- 中华珍宝馆内部可见、数字端不可见
- 锦江故事读取真实物件与照片
- 策展预案可实际发布入库
- “正在发生”读取已发布数据库展览
- 运营后台读取渠道、漏斗和内容信号
